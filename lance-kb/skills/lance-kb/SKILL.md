# 本地知识库（LanceDB）

资料存在本机 `data/lancedb/`，用 LanceDB 存片段与向量，混合检索（向量 + 全文 RRF）返回带出处的
片段。**整个过程不联网、不出机器**（除非显式配了远端 embedding 接口）。

回答用户问题前，**先 `kb_search` 检索，再基于返回片段作答**。不要凭记忆编用户资料里的内容——
用户之所以建这个库，就是要一个可追溯的来源。

## 可用工具

| 工具 | 用途 |
|---|---|
| `kb_stats` | 库概况：文档/片段/字数、类型分布、标签、嵌入后端与维度、全文分词器、库路径、来源目录。**回答前先调它** |
| `kb_add` | 入库：`paths`（文件/目录/通配，递归）或 `name`+`text`（一段文字）。按内容哈希增量，没改的跳过 |
| `kb_search` | 混合检索：`mode=hybrid`（默认）/`vector`/`keyword`，可叠 `doc_type`/`tags`/`path_prefix` |
| `kb_open` | 取上下文：给 `chunk_id` 拿前后各 N 个片段；给 `doc_id` 看文档开头 |
| `kb_docs` | 文档清单：按名字/类型/标签过滤，`order=updated\|added\|name\|chunks\|size` |
| `kb_remove` | 删文档：`doc_ids` / `path_prefix` / `pattern`(glob) / `tags` / `all` |
| `kb_reindex` | 重建向量与全文索引（换嵌入后端、改切块参数后必用） |
| `kb_sync` | 重扫已登记目录：新增/变更入库，源文件消失的清理 |
| `open_dashboard` | 打开库看板（类型分布、标签、文档清单、片段浏览）；看板里能直接拖文件入库 |

## 数据模型

```
docs    一个文件/一条笔记一行：doc_id、名称、路径、类型、片段数、字数、tags、内容哈希、时间
chunks  一个片段一行：chunk_id(=doc_id#序号)、doc_id、heading(小节路径)、text、ordinal、vector
```

- `doc_id` 由文件绝对路径哈希得出，**同一路径重入库会覆盖旧记录**（不会越加越多）。
- 笔记（`kb_add` 的 `name`+`text` 模式）`doc_path = note://<标题>`，`doc_type = note`。
- 全文索引建在 `search_tokens`（jieba 切好的词，空格连接，含小节标题）上，`base_tokenizer="whitespace"`；
  没装 jieba 时退回 `search_text` + `ngram(2-3)` 字符切片。当前是哪一种看 `kb_stats.fts_tokenizer`。
- 向量列维度由嵌入后端决定；中文场景优先 `bge-m3`（ollama）或 `bge-small-zh-v1.5`（fastembed）。
- 库目录可用 `LANCE_KB_HOME` 改，默认插件下 `data/`。

## 检索策略（别只会 hybrid 一把梭）

1. **默认 hybrid**：向量召回 + 全文召回各取前 N，RRF 融合。多数问题的答案在这里。
   中文查询直接写自然语言整句就行（「灰度发布失败怎么回滚」），jieba 会切词，
   不需要先手动拆关键词。
2. **答案里出现错别字/专有名词/代码符号**（函数名、配置项、错误码）→ `mode=keyword`，
   字面匹配比语义更可靠。
3. **用户换着说法描述概念**（「怎么做灰度发布」→ 文档里写的是「分批上线」）→ `mode=vector`。
4. **命中不准时调整范围**再调 k：`doc_type=md` 排除代码噪声，`path_prefix` 锁定项目目录，
   `tags` 锁定标签。
5. 返回的 `truncated=true` 说明片段被截断，需要完整段落/代码就用 `kb_open(chunk_id=...)`
   取上下文，别拿半截话当结论。

## 引用与口径（必须遵守）

- 引用格式统一写 **「文档名 › 小节标题」**，例如 `部署手册 › 灰度发布`；有路径就一并给出。
- 检索不到就直说「知识库里没有相关内容」，并建议用户先 `kb_add` 收录哪个目录，
  **不要用常识补全用户资料**。
- `kb_stats` 里 `embedder` 若是 `hash/...`，说明用的是兜底哈希向量（没有语义泛化能力），
  此时**必须配合 keyword 或 hybrid**，且要提醒用户：想提升语义召回就起 ollama 拉 `bge-m3`，
  或装 `fastembed`，然后 `kb_reindex`。别在这种状态下吹「语义搜索」。
- 片段数、字数会随切块参数变化；报「库里有多少内容」用文档数 + 总字数，别报片段数当文档数。

## 入库套路

- 用户说「把这个目录记下来」→ 先确认路径，再 `kb_add(paths=[...], tags="...")`，
  回报新增/更新/跳过/失败的数量和总文档数。目录很大（>2000 文件）时先问一句要不要限定子目录。
- 用户给了一段结论/会议纪要要存 → `kb_add(name="...", text="...", tags="...")`，不要落成文件再索引。
- 反复收录同一个目录（保鲜）→ 用 `kb_sync`，别每次全量 `kb_add`；也可以建议做成定时任务：
  「每天早上 9 点同步本地知识库」。
- 删之前一定要确认范围：`kb_remove` 不可撤销；先 `kb_docs(query=...)` 让人看清楚要删哪些。
- 换嵌入后端（`LANCE_KB_EMBED=ollama`）后如果维度变了，工具会报「库里是 X 维，当前是 Y 维」，
  这时必须 `kb_reindex` 全量重建，不能靠重新 `kb_add` 糊过去。

## 支持的格式

`md / txt / pdf / docx / html / csv / tsv / json / yaml / ipynb / 常见代码文件`（py、js、ts、vue、
java、go、rs、sql、sh、css…）。

- PDF 需要 `pypdf`、DOCX 需要 `python-docx`，没装时那个文件会记一条失败，其余照常入库。
- 递归扫描会跳过 `.git`、`node_modules`、`.venv`、`dist`、`build` 等目录与锁文件。
- 单文件上限 8MB；疑似二进制的直接跳过（不会把图片塞进库）。

## 回答套路

- **「我的资料里 X 是怎么说的」**：`kb_search(q, k=8)` → 挑 2-4 个最相关片段 → 用「文档名 › 小节」
  标出处作答；多份文档说法不一致时，明确指出分歧和各自出处，别糅成一段。
- **「库里有啥」**：`kb_stats` 报文档数/字数/类型分布/最近更新，再 `kb_docs` 列几条代表性的。
- **「某个文件收进来了吗」**：`kb_docs(query="文件名片段")`。
- **要图/要浏览**：`open_dashboard`，打开后**别再复述一遍数字**，只说能怎么筛。
  用户说「我自己传几个文件」时也开看板——里面的「添加文件」区支持拖拽/多选，
  入库后页面会自己刷新，不用再让我 kb_add。
  用户说「我自己传几个文件」时也开看板——里面的「添加文件」区支持拖拽/多选，
  入库后页面会自己刷新，不用再让我 kb_add。
- **库是空的**：明确告诉用户「还没有索引任何资料」，给出 `kb_add` 的具体建议路径，别硬答。
